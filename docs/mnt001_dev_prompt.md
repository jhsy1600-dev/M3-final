# MNT-001 개발 지시서: 계획을 넘는 학습 실적의 달성률 표시

작성: PM, 2026-11-23. **발행 조건: 사용자 승인 후**. 근거: `docs/operations_maintenance_log.md` MNT-001. 이 작업만 한다. 운영유지보수(오류) 작업이므로 변경관리 CR 과 개발 완료보고서에 올리지 않는다.

## 1. 원인(PM 확인)
서버는 실적을 상한 없이 누적한다(과제 합계, 주간 합계, 일자별 합계). 화면 표시만 100%에서 멈춘다.
- `frontend/lib/executionView.ts` 의 `goalStat`: `Math.min(100, Math.round((minutes / target) * 100))` → 목표를 넘어도 100%.
- `frontend/components/ExecutionScreen.tsx` 약 514행: 과제별 진행 막대 폭 `Math.min(100, …)`(폭 상한은 정상, 아래 2번 참고).
- 대시보드의 같은 지표(`Dashboard.tsx` 약 212행 `weeklyAchievementPercent`)는 상한이 없어 화면 사이에 값이 다르다.

## 2. 해야 할 일 (표시만, 서버·데이터·진행률 정의는 건드리지 않는다)
1. **주간 목표 달성(실행 화면):** `goalStat` 의 상한을 없애고 실제 비율을 표시한다(예: 목표 420분에 714분이면 `170 %`). `detailText`("714분 / 420분")는 그대로. 대시보드와 같은 값이 나와야 한다.
2. **과제별 진행 막대:** 막대 폭은 100%에서 멈추게 둔다(레이아웃 보호). 대신 과제 메타 줄 `계획 N분 · 실제 M분 · 기록 K건` 에서 **실제 시간이 계획을 넘으면** `실제 M분(NNN%)` 처럼 계획 대비 비율을 덧붙인다(예: `계획 60분 · 실제 470분(783%) · 기록 3건`). 넘지 않으면 지금과 같다.
3. **하지 않는 것:** `progress_percentage`(완료 과제 수 / 전체 과제 수, 핵심 결정이라 100%를 넘을 수 없음), 분석 화면의 일자별 막대(이미 누적이며 폭은 주 내 최댓값 대비), 서버 계산, 문구의 다른 변경, 색·크기·레이아웃.
4. 기존 테스트가 상한(100)을 확인하면 새 동작으로 고치고 보고한다. 새 테스트: 목표 대비 170%일 때 `goalStat` 이 `170` 을 돌려준다, 목표 이하와 경계값(100%), 과제 meta 의 비율 덧붙임(넘는 경우와 아닌 경우), 목표 없음·전체 기간은 이전과 같다.
