# 회고 Long-term Memory 동작 사례 (TASK 10.2)

작성: PM, 2026-11-23. 목적: AI 튜터가 **본인의 저장된 회고**를 참고해 답한다는 것을 실제 호출로 보이는 사례. 근거 규칙은 PRD FR-05, `GET /api/data/summary`(진행 중 학습 요약과 최근 회고 최대 5건, 질문 키워드 일치 우선)를 튜터 시스템 프롬프트에 넣는 구조다.

## 1. 시험 방법
- 로컬 `dev` 인증, 메모리 저장소(운영 데이터와 무관), **실제 OpenAI 호출**(튜터 모델 `gpt-4o-mini`), 가상 사용자.
- 학습: Python 개발 / 기본문법, 과제 "자료형과 변환".
- 저장한 학습 기록 1건(자료형 변환 연습 40분)과 회고 1건: *"문자열 "42"를 숫자로 바꾸는 int() 변환이 자꾸 헷갈린다. 정수와 실수 변환 차이를 다시 정리해야 한다."* (태그: 어려움)
- 같은 대화에서 질문 두 가지를 보냈다: 회고와 관련 있는 질문, 관련 없는 대조 질문. (대조 질문은 첫 실행에서 일시적 연결 오류가 나서 같은 조건의 새 저장소에서 한 번 더 호출했다. 두 번째 실행의 저장 상태는 첫 실행과 같다.)

## 2. 결과
| 질문 | 답변 요지 | 회고 반영 |
|---|---|---|
| **관련:** "문자열을 숫자로 바꾸는 방법이 헷갈려요." | `int("42")`, `float("3.14")` 설명과 함께 **"헷갈리시는 부분은 정수와 실수의 변환 차이로 보이는데, …"** 라며 두 변환의 차이를 짚음. 참고 자료로 "Python 공식 튜토리얼 — 기본 문법"을 출처로 표시 | **반영됨.** 질문에는 "정수와 실수"가 없었고, 회고에만 있던 "정수와 실수 변환 차이"가 답변에 나타남 |
| **대조(무관):** "for 반복문은 어떻게 쓰나요?" | `for` 문법, `range()` 예시. 같은 출처 표시 | **나타나지 않음.** 회고를 억지로 끼워 넣지 않음(질문과 관련 있을 때만 참고하라는 프롬프트 규칙과 일치) |

## 3. 해석과 한계
- 같은 저장 상태에서 질문에 따라 회고가 쓰이기도, 쓰이지 않기도 했다는 점이 핵심이다. 회고가 항상 붙는 고정 문구가 아니라 **질문과 관련될 때 맥락으로 쓰인다.**
- 답변이 "회고를 참고했다"고 직접 말하지는 않았다. 반영 여부는 **회고에만 있던 내용이 답변에 나타난 것**으로 판단했다.
- 질문당 1회 호출한 결과다. 생성형 모델은 호출마다 답이 다를 수 있어 같은 문장이 다시 나온다고 보장하지 않는다. 반복 비율은 측정하지 않았다.
- 시험 스크립트는 저장소에 두지 않았다(임시 파일). 규칙의 코드 근거는 `backend/main.py` 의 튜터 처리(`_learning_context`)와 `docs/phase6_*` 검증 기록.
- 발표용 화면 캡처(회고 입력 → 튜터 답변)는 사용자가 운영 화면에서 따로 확보한다.
