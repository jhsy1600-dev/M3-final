# CR-028 개발 지시서: Next.js 보안 업데이트(빌드 중단 해소)

작성: PM, 2026-11-23. 근거: 변경관리 CR-028(`docs/change_management.md`), 사용자 승인(2026-11-23 "그 순서로 진행"). 이 작업만 한다. CR-026 지시서(`docs/cr026_dev_prompt.md`)는 이 작업이 PM 검증을 마친 뒤에 따로 전달한다. **지금 열어 보거나 시작하지 않는다.**

## 1. 배경
`npm run build` 가 컴파일과 정적 페이지 생성까지 성공한 뒤 **종료 코드 1**로 끝난다(PM 이 직접 재현). 출력의 원인은 `SecurityFatalError`: 설치된 Next.js(16.4.2, `frontend/package.json` 은 `^16.0.0`)가 알려진 보안 취약점 대상이라는 점검에서 중단된 것이다. 개발팀 보고(CR-022)에 따르면 코드 변경 없이도 같은 결과다. Vercel 의 배포 빌드가 같은 점검에서 실패하면 프론트를 배포할 수 없으므로 push 전에 해결해야 한다.

## 2. 해야 할 일
1. **원인과 고칠 버전을 근거와 함께 확인한다.**
   - 점검이 가리키는 권고와 어느 버전부터 안전한지를 보고서에 적는다(출력에 나온 참조 주소, `npm view next dist-tags`, `npm view next versions` 등으로 확인).
   - **같은 메이저(16.x) 안에서 가장 낮은 안전 버전**을 고른다. 메이저를 올리지 않는다(17.x 등은 하지 않는다).
2. **`next` 만 올린다.** `npm install next@<고른 버전>` 으로 `frontend/package.json` 과 `package-lock.json` 을 함께 갱신한다. 빌드가 요구하는 경우가 아니면 `react`, `react-dom` 등 다른 의존성은 올리지 않는다(올렸다면 이유를 보고서에 적는다).
3. 업그레이드 명령을 실행하는 도구(`next upgrade ...` 등)가 파일을 자동으로 만들거나 바꾸면 그 변경을 확인한다. 의도하지 않은 파일 변경은 되돌린다. 특히 `frontend/AGENTS.md` 는 Next.js 가 자동 생성하는 파일이고 사용자가 커밋 여부를 정하지 않았으므로 **커밋에 넣지 않는다.**
4. 아래 검증을 통과시킨다. 버전을 올려서 깨지는 곳이 있으면 **고치지 말고 보고한다**(범위 밖이면 PM 이 CR 로 따로 받는다). 단 설정 파일의 아주 작은 호환 조정(예: 더 이상 쓰지 않는 옵션 이름)은 허용하고 보고서에 적는다.

## 3. 하지 않을 것
- 화면, 문구, CSS, 컴포넌트 로직, 백엔드는 건드리지 않는다. 다른 CR(021, 023~027)은 시작하지 않는다.
- 취약점 점검을 끄거나 우회하는 방법(환경변수, `--no-...` 옵션, 점검 코드 삭제)을 쓰지 않는다. 버전을 올려서 해소한다.
- 메이저 업그레이드, 패키지 매니저 변경, Node 버전 변경을 하지 않는다.

## 4. 검증 요구
- `npm run typecheck` 통과, `npm test` 통과(기준 249건, 숫자를 보고서에 적는다), **`npm run build` 가 종료 코드 0** 으로 끝난다(종료 코드를 `echo $?`/`$LASTEXITCODE` 로 확인해 보고서에 적는다).
- 업그레이드 전후의 `next` 버전, `package-lock.json` 에서 바뀐 패키지 수를 보고서에 적는다(`git diff --stat`).
- `npm run dev` 로 첫 화면이 열리는지 확인한다. 브라우저 확인이 어려우면 "미검증"으로 쓴다.
- 새 취약점 점검 메시지(`npm audit` 등)가 남아 있으면 목록을 보고서에 적는다(고치지 않는다).

## 5. [필수] 완료 조건

- **로컬 커밋만 하고 push 하지 않는다.** 개인 파일(`frontend/AGENTS.md`, 변경관리내역서 hwp·pdf, `docs/프롬프트와 응답사례연구.md`)은 커밋에 넣지 않는다. 채팅에는 완료 여부, 테스트 통과 수, 빌드 종료 코드, 보고서 경로만 간단히 보고한다.
