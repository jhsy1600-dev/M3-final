# 사용자 의견 → 개선 대응표 (발표·평가용: 피드백 및 개선 20%)

작성: PM, 2026-11-10 (CR-017). 근거는 `docs/change_management.md`(CR-001~015), `docs/ai_improvement_log.md`(IMP-001~010), `docs/user_test_round1.md`, `docs/change_review_learning_path.md`, 변경관리내역서. 계기 칸은 각 문서에 적힌 것을 옮겼고 추측하지 않았다.

**누가 "사용자"인가(솔직하게 적는다):** 테스트는 2026-10-22 첫 확인부터 팀원 본인이 학습자 관점에서 직접 써 보며 의견을 낸 것(1차, 내역서, 화면 캡처)과, 2026.11.01~11.20 외부 테스터 설문(진행 중, 결과는 끝난 뒤 추가)으로 나뉜다. **아래 표의 의견 대부분은 앞의 팀원 사용자 테스트에서 나왔다.** 외부 테스터 설문 반영은 11.20 이후 이 문서에 이어 쓴다.

## 3. 평가 기준에 쓸 수 있는 요약
- **대응 기록이 있는 항목**: CR 15건, AI 개선 IMP 10건, 1차 테스트 의견 7건(번호 5 는 원문에 없음).
- **계기별 CR 수(변경관리 문서 §3 의 결정·요청 열 기준)**: 사용자 지적·요청·결정·사용 중 발견이 **12건**(001, 002, 004, 005, 006, 007, 009, 010, 012, 013, 014, 015), PM 이 점검·화면 확인 중 찾아 지시한 것이 **3건**(003 영어 응답, 008 동의 문구 정리, 011 TASK 재점검). CR-014 는 내역서 요청이며 그 안의 E-1(분모 오류)은 PM 이 코드에서 찾았다. CR-007 은 CR-006 에 흡수, CR-006 은 설계 후 보류 중이다.
- **AI 출력 신뢰성**은 사용자 의견과 별개로 PM 검증에서 나온 개선이다: IMP-003(인사이트 숫자 오류 → 서버 계산), IMP-001·002(근거 조각 검토, 출처를 서버가 붙임). 발표에서 "AI 결과를 서버가 보장하는 설계"의 근거로 쓴다.
- **효과를 측정한 것**: 영어 응답 12회 중 0회(CR-003), 인사이트 재시도 비용 감소(IMP-003 2차), 계획 품질 사용자 체감(IMP-010). 나머지는 "측정 예정" 또는 "dev 기준"이며 **배포 환경의 사용자 지표는 아직 없다**(설문 11.20 종료 후).

## 4. 남은 일 (외부 테스터 설문 결과가 나오면)
1. 설문 응답 요약을 `docs/user_test_survey_result.md` 로 정리(원문은 올리지 않고 요약만).
2. 설문에서 나온 새 의견을 위 표에 행으로 추가하고 CR 번호를 부여.
3. README §9 "결과"와 발표 "사용자 테스트" 슬라이드에 반영.
