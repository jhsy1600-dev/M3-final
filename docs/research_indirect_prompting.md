# 연구: 간접 프롬프팅으로 계획 품질을 높인 과정 (발표·평가용 정리)

작성: PM, 2026-11-23. 근거: `docs/plan_prompt_test_2026-11-09.md`(1~3차 반복 시험), `docs/plan_prompt_v2_draft.md` §6~7, `docs/ai_improvement_log.md` IMP-010, `docs/cr012_verification.md`, 사용자 사례 연구 자료(`docs/프롬프트와 응답사례연구.md`, 사용자 개인 파일이라 이 문서에는 내용을 옮기지 않고 요지만 쓴다). 이 문서는 **측정된 것과 사용자가 체감한 것을 구분해서** 쓴다.

## 1. 문제 제기: 같은 질문, 다른 결과
- **기준 사례(사용자 자료):** 일반 대화형 AI 에 가톨릭 성경 완독 계획을 묻자, 성경 각 권의 분량과 필요 시간을 먼저 추정해 "가용 시간보다 더 필요하다"는 점과 해결 방법까지 짚고 구체적인 계획과 인사이트를 줬다.
- **초기 PaceMate(단일 호출):** 같은 입력(영역·과정·목표)에서 계획이 빈약했고, 반복 시험에서 **성경 계획 5번 중 첫 시도에 통과한 것이 0번**(재시도 후 성공 4번, 실패 1번)이었다. 성공한 계획에도 **가톨릭 성경 계획에 개신교 책 이름**(출애굽기, 하나님 등)이 섞였다(맞는 용어 1 대 틀린 용어 32).
- 원인: 한 번의 호출이 "영역 지식 판단"과 "과제 목록 설계", "형식 맞추기"를 한꺼번에 했고, 작은 모델(`gpt-4o-mini`)은 "가용 시간을 넘지 마라"만 받아 범위를 줄이는 판단을 하지 못했다.

## 2. 해결 방식: AI 가 AI 에게 줄 지침을 먼저 만든다 (간접 프롬프팅)
계획 생성을 **3번의 호출**로 나눴다(CR-012).
| 단계 | 하는 일 | 입력 → 출력 |
|---|---|---|
| 0단계 | **영역별 학습 설계 지침**을 AI 가 먼저 쓴다("이 영역의 과제는 어떤 단위로 나누고 어떤 순서로 하며 공식 명칭은 무엇인가") | 분야·과정 → 자유 글(지침) |
| 1단계 | 0단계 **지침 + 학습자 조건**(기간, 주당 시간, 수준)으로 설계 의견을 쓴다 | 지침 + 조건 → 자유 글(의견) |
| 2단계 | 의견을 정해진 **JSON(과제 목록, 조언)**으로 정리한다. 서버가 규칙을 검증하고 어기면 거부·재시도 | 의견 → JSON |
- **서버가 하는 일(바뀌지 않음):** 주차·요일 배치와 시간 합계는 서버가 계산하고 AI 결과는 서버가 스키마와 규칙으로 검증한다. 지침은 **저장하지 않고 요청마다 새로 만든다**(사람 검토 없이 저장하면 틀린 지침이 모든 학습자에게 퍼지기 때문).
- **사용자 제안:** "영역·과정마다 과제를 어떻게 도출할지 먼저 AI 에게 묻고, 그 답을 다시 프롬프트로 써서 계획을 만들게 하자"(2026-11-09).

## 3. 이 기법에 이름이 있는가 (확인한 문헌)
정확히 같은 이름의 기법은 없지만 **가까운 계열**이 있다. 아래 논문은 PM 이 제목과 요지를 확인했다.
| 이름 | 요지 | 우리 방식과의 관계 |
|---|---|---|
| **프롬프트 체이닝**(Prompt chaining, 설계 패턴) | 한 작업을 순서가 있는 여러 AI 호출로 나누고 앞 출력이 뒤 입력이 된다 | **전체 구조** |
| **생성 지식 프롬프팅**(Generated Knowledge Prompting, Liu 외, ACL 2022) | 모델이 먼저 질문에 관한 지식 문장을 생성하고 그것을 추가 입력으로 답한다 | **0단계(영역별 지침 생성)와 가장 가깝다.** 지식의 품질·양·통합 방식이 성능을 좌우한다는 분석이 우리 결과(지침의 질은 모델 크기에 좌우)와도 맞는다 |
| **스텝백 프롬프팅**(Step-Back Prompting, Zheng 외, ICLR 2024) | 구체 질문에서 한 걸음 물러나 상위 원리를 먼저 끌어낸 뒤 그 원리로 푼다 | 0단계가 "이 영역의 과제 단위와 순서"라는 상위 원리를 먼저 끌어내는 점이 비슷하다 |
| **자동 프롬프트 엔지니어**(APE, Zhou 외, 2022) / **메타 프롬프팅**(Suzgun & Kalai, 2024) | 모델이 다른 모델 호출에 줄 지시문을 쓰거나(APE), 한 모델이 지휘자가 되어 전문가 호출에 지시한다(메타 프롬프팅) | **"AI 가 AI 에게 줄 지침을 쓴다"는 발상**이 같다. 다만 APE 처럼 후보 지시문을 만들어 점수로 고르거나 메타 프롬프팅처럼 지휘자·전문가 구조를 쓰지는 않았다 |
- **발표에서 쓸 이름 제안:** **"간접(메타) 프롬프팅 기반 3단계 체이닝 — 영역별 지침을 먼저 생성"**. 정확히 같은 기법이라고 주장하지 않고 "가까운 연구 계열을 참고해 설계"라고 쓴다.
- 출처: [Generated Knowledge Prompting for Commonsense Reasoning](https://arxiv.org/abs/2110.08387), [Large Language Models Are Human-Level Prompt Engineers](https://arxiv.org/abs/2211.01910), [Take a Step Back: Evoking Reasoning via Abstraction in LLMs](https://arxiv.org/abs/2310.06117), [Meta-Prompting: Enhancing Language Models with Task-Agnostic Scaffolding](https://arxiv.org/abs/2401.12954).

## 4. 결과: 측정한 것과 체감한 것
시험은 모두 실제 OpenAI 호출, 같은 입력을 반복(분야 5개, 회당 3~5번)했다. **표본이 작고 PM 이 직접 표본을 읽어 판정했다.**
| 지표 | 단일 호출(초기) | 2단계(V3) | 3단계(영역 지침) + 큰 모델(gpt-5.4-mini) |
|---|---|---|---|
| 가톨릭 성경 계획 성공 | 3/5(2차 시험), 4/5이지만 첫 시도 통과 0(1차) | **5/5, 첫 시도 5** | 2/3(실패는 모두 2단계 JSON 정리) |
| 가톨릭 성경 계획의 **가톨릭 명칭 수**(3회 합) | 0 | 0 | **11**(개신교 명칭 8) |
| 정보처리기사 **공식 과목명**(5개 중, 회별) | 0~1 | 0~1 | **2, 5, 5** |
- **사용자 체감(배포 화면, 2026-11-09): "종전보다 훨씬 나아졌다, 거의 2배 이상 좋아졌다."** 이것은 한 사람의 체감이며 측정이 아니다.
- **"10배 이상"은 기록된 측정으로 뒷받침되지 않는다.** 일부 지표(가톨릭 명칭 0 → 11, 공식 과목명 0 → 평균 약 4)는 0에서 큰 값으로 올라 배수를 말할 수 없고, 표본이 3~5회이며, 구조와 모델이 **함께** 바뀌었다. **발표에서는 배수가 아니라 위 수치 그대로** 쓰고, 체감은 "사용자 체감"으로 구분한다.
- **중요한 한계(시험이 보여 준 것):** 같은 3단계 구조도 작은 모델(`gpt-4o-mini`)에서는 얕았다(가톨릭 명칭 0, 공식 과목명 0). **구조는 실패를 줄이고(안정성) 영역 지식은 모델 크기가 좌우한다.** 큰 모델도 명칭이 완전하지 않았고(출애굽 사건명 등), 1단계 글에서 존재하지 않는 판본 이름("제2천주교 성경")을 지어낸 경우가 있었다(2차 시험, V3). 그래서 서비스 화면에 "AI 가 만든 계획이며 명칭·분량은 교재로 확인" 안내를 유지한다.
- 비용·시간: 계획 1건당 호출 3번(합계 약 25~34초, 토큰은 모델에 따라 `docs/plan_prompt_test_2026-11-09.md` 3차). 비용은 OpenAI 요금표로 따로 확인한다(PM 은 추정하지 않음).

## 5. 더 다듬으면 (표준화 방향)
| 방향 | 내용 | 기대 효과 | 위험 |
|---|---|---|---|
| ① 지침 저장·검토·재사용 | 영역별 지침을 저장하고 **관리자가 검토·수정**한 뒤 재사용(현재는 요청마다 새로 생성) | 같은 영역에서 같은 품질, 비용·시간 감소 | 검토 없이 저장하면 틀린 지침이 모두에게 퍼진다 → 사람 검토 필수 |
| ② 지침의 틀 표준화 | 지침이 항상 포함할 항목을 정한다: 과제 단위, 순서, 필요량 추정, 공식 명칭, 불확실한 것은 "확인 필요" | 출력의 일관성 | 틀이 너무 엄격하면 영역 특성이 사라진다 |
| ③ RAG 와 통합 | 검토된 자료(판본 이름, 공식 과목명)를 지침 생성에 함께 넣는다 | 명칭 오류 감소(지어낸 판본 이름 방지) | 자료가 있는 분야에만 효과 |
| ④ 평가 세트 만들기 | 분야 5개 × 5회 이상, 같은 지표(성공률, 첫 시도 통과, 명칭 정확도, 공식 과목명, 구체성, 시간 합계, 토큰)로 변경마다 회귀 시험 | "좋아졌다"를 측정으로 말할 수 있다 | 표본 설계와 판정 비용 |
| ⑤ 모델 정책 | 지침·의견 단계는 큰 모델, JSON 정리는 같은 모델 또는 검증 강화 | 실패 지점(2단계) 감소 | 비용 증가 |
- ①은 이미 후속 계획으로 기록되어 있다(`docs/plan_prompt_v2_draft.md` §7, IMP-010 후속, 통합 RAG는 CR-012 후속).

## 6. 발표에서 어떻게 보일까 (슬라이드 제안)
- **슬라이드 A "같은 질문, 다른 결과"**: 일반 AI 답(분량 추정·가용 시간 비교) / 초기 PaceMate(빈약, 개신교 명칭 혼입) 두 열 비교.
- **슬라이드 B "AI 가 AI 에게 지침을 쓰게 한다"**: 3단계 흐름도(지침 → 의견 → JSON) + "서버가 검증하고 계산" + 가까운 연구 계열(생성 지식 프롬프팅, 스텝백, 메타 프롬프팅) 한 줄.
- **슬라이드 C "측정 결과와 한계"**: 4장의 표 3행 + "사용자 체감 2배 이상(측정 아님)" + "구조는 안정성, 영역 지식은 모델 크기" + 다음 단계(표준화 ①~④).
