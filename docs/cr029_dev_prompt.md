# CR-029 개발 지시서: 작성 중 화면 이동 경고창을 3버튼(이동 / 계획 제거 / 취소)으로

작성: PM, 2026-11-24. 근거: `docs/change_management.md` CR-029(개선). 이 작업만 한다. 오류가 보이면 보고서가 아니라 `docs/operations_maintenance_log.md` 후보로 PM 에게 알린다.

## 1. 배경 (현재 동작, PM 이 코드로 확인)
- `frontend/components/LearningPathWizard.tsx` 534~543행: 작성 중(`recommendation != null || draft != null`)이고 저장 완료가 아니면, 사이드바로 다른 화면에 가려 할 때 `window.confirm("작성 중인 학습 경로·계획이 있습니다. 저장하지 않고 다른 화면으로 이동할까요?")` 를 띄운다(브라우저 기본 창, 확인·취소 2개). 이동 보호는 `frontend/app/page.tsx` 의 `go()` 가 `leaveGuard.current()` 를 **동기 boolean** 으로 호출하는 방식이다(123행).
- 작성 내용은 `frontend/lib/wizardStorage.ts`(sessionStorage)에 매번 자동 보관되고(LearningPathWizard 495행 `saveWizardDraft`), 돌아오면 복원된다(132행 `loadWizardDraft`). 즉 **이동해도 내용은 사라지지 않는데 문구는 "저장하지 않고"** 라서 사용자가 오해한다.
- 보관된 초안을 지우는 방법이 없다(`clearWizardDraft` 호출은 확정 저장 460행, 로그아웃·데이터 삭제 `AuthProvider.tsx` 뿐). 그래서 작성을 시작하면 끝까지 저장해야 하는 것처럼 보인다.
- 초안은 서버에 저장되지 않는다(계획은 확정할 때만 저장). **서버·DTO 는 바꾸지 않는다.**

## 2. 해야 할 일
1. 이동 경고를 브라우저 `window.confirm` 대신 **앱 안 대화상자(모달)** 로 바꾼다. 버튼 3개, **이 순서**:
   - **이동**: 작성 내용을 그대로 보관한 채 요청한 화면으로 이동한다(돌아오면 이어 쓸 수 있음, 현재 동작과 같음).
   - **계획 제거**: 작성 중인 경로·계획을 지우고(`clearWizardDraft()` 와 위저드 상태 초기화) 요청한 화면으로 이동한다. 돌아오면 빈 화면에서 시작한다.
   - **취소**: 아무것도 바꾸지 않고 현재 화면에 머문다.
2. 문구: 제목 없이 본문만 쓴다. 본문은 **"작성 중인 학습 경로·계획이 있습니다. 이동해도 이 탭에서는 내용이 보관되어 돌아오면 이어서 쓸 수 있습니다. 완전히 지우려면 '계획 제거'를 누르세요."** (탭을 닫으면 사라진다는 점은 한 줄로 덧붙여도 된다: "탭을 닫으면 사라집니다.")
3. 이동 보호 방식을 바꾼다. 모달은 비동기라 `go()` 가 boolean 을 기다릴 수 없다. 방식은 개발팀이 정하되 조건: (a) 사이드바로 이동하는 **모든 경로**(메뉴 클릭, 화면 안의 이동 버튼 등 `go()` 를 쓰는 곳)가 같은 보호를 받는다, (b) 보호할 것이 없을 때(작성 내용 없음, 저장 완료 `confirmStatus === "done"`)는 모달 없이 바로 이동한다, (c) 대화상자가 떠 있는 동안 다른 이동을 시작하지 못한다.
4. **계획 제거 시 주의(중요):** 위저드는 상태가 바뀔 때마다 `saveWizardDraft(snapshot)` 를 호출한다(495행). 제거 직후 이 효과가 빈 상태나 이전 상태를 다시 저장해서 **초안이 되살아나지 않게** 한다(제거 후 이동했다가 돌아오면 반드시 빈 시작 화면). 이동 후 위저드가 사라지는 시점과의 순서를 확인해 방지한다.
5. 접근성: 열리면 **"취소" 버튼에 초점**을 둔다(되돌릴 수 없는 "계획 제거" 가 기본이 되지 않게). `Esc` 는 취소와 같다. 대화상자에 `role="dialog"` 와 `aria-modal`, 제목 대신 `aria-label` 또는 본문 연결. 초점이 대화상자 밖으로 나가지 않게 한다.
6. 스타일: **새 색·새 CSS 규칙을 만들지 않는다.** 앱에 이미 있는 모달(`ConsentModal.tsx`)과 버튼 클래스를 재사용한다. 3개 버튼 중 "계획 제거" 는 파괴적 동작이라 눈에 덜 띄는 보조 버튼 모양, "이동" 은 주 버튼 모양, "취소" 는 보조 버튼 모양을 쓴다. 현재 테마(CR-027)의 기존 클래스 범위에서 정한다.

## 3. 하지 않을 것
**경고를 띄우는 조건(`hasProgress` = 과정 추천 결과 또는 초안이 있을 때)은 그대로 둔다.** 분야·목표만 입력한 단계는 지금처럼 경고 없이 이동하고 입력은 자동 보관된다(변경하지 않는다). 서버, DTO, 초안 보관 방식(sessionStorage)과 복원 규칙, 로그아웃·데이터 삭제 시 초안 삭제, 위저드 화면 안의 다른 버튼 추가(별도 "초안 지우기" 버튼은 이번 범위가 아니다), 브라우저 탭 닫기·새로고침 경고(`beforeunload`), 다른 화면(AI 튜터, 실행 기록 등)의 이동 보호, 색·레이아웃의 다른 변경.
