# CR-022 개발 지시서: 학습경로 미리보기 숫자에 시간 단위 표시

작성: PM, 2026-11-20. 근거: 앱 내 사용자 피드백(2026-11-12, "미리보기의 900, 1200 같은 숫자 옆에 시간 단위를 표시해 주세요"), 변경관리 CR-022(`docs/change_management.md`), 요약 `docs/user_feedback_2026-11.md`. 이 작업만 한다. 다른 CR(021, 023, 024)은 시작하지 않는다.

## 1. 배경
`frontend/components/LearningPathWizard.tsx` 의 학습 과제 목록(학습경로 미리보기, 약 919~927행)에서 과제별 예상 학습 시간을 `<input type="number">` 로 받는데, 눈에 보이는 단위가 없고 `aria-label="예상 학습 시간(분)"` 에만 "분"이 있다. 사용자는 900, 1200 같은 숫자가 무엇인지 알 수 없다고 했다.

## 2. 해야 할 일
1. 위 입력칸 옆(또는 입력칸 안쪽 끝)에 눈에 보이는 단위 **"분"** 을 표시한다. 라벨이나 접미 글자 중 기존 화면 구조를 가장 덜 바꾸는 방식을 고른다.
2. **같은 화면 흐름에서 단위 없는 시간 숫자가 더 있는지 전수 확인한다.** 대상: 학습경로 미리보기(Wizard 의 학습 과제 탭), 과제 계획 화면(`WeeklyPlanScreen.tsx`), 주차 머리글(`weekGroupHeading` 등), 이어짐 표시(`continuedLabel`). 이미 "분"이나 "시간"이 붙어 있는 곳은 그대로 둔다. 새로 찾은 곳이 있으면 보고서에 목록으로 적고 같이 고친다(범위: 시간 숫자의 단위 표시에 한정).
3. 접근성 라벨(`aria-label`)은 유지한다.
4. 큰 숫자(예: 900분)가 입력칸 안에서 잘리지 않아야 한다. 입력칸 너비가 부족하면 최소한으로 조정한다.

## 3. 하지 않을 것
- 시간 단위를 "시간·분"으로 환산해 바꾸지 않는다(900분을 15시간으로 바꾸지 않는다). 사용자 요청은 "단위 표시"이다.
- API, DTO, 데이터, 백엔드는 건드리지 않는다. 글자 크기 하한(CR-015)을 깨지 않는다(새 글자는 기존 `small`/라벨 크기를 따른다).
- 목업(`mockup/index.html`)에는 이 과제 편집 행이 없다. 비슷한 입력칸(`record-minutes`)이 **라벨에 "(분)"을 보이는 방식**이므로 같은 느낌을 따르되, 목업은 수정하지 않는다(PM 소유).

## 4. 검증 요구
- `npm run typecheck`, `npm test`, `npm run build` 통과. 통과 수는 보고서에 숫자로 적는다(기준: CR-014 시점 246).
- 단위 표시를 확인하는 테스트를 최소 1개 추가한다(해당 입력칸 근처에 "분"이 보이는 것).
- 화면 폭 3종(넓은 화면, 태블릿, 휴대폰)에서 입력칸과 단위가 겹치거나 잘리지 않는지 확인하고, 확인하지 못했으면 "미검증"이라고 쓴다.
