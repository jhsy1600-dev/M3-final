# 사용자 피드백 대장 (건수 정의와 목록)

작성: PM, 2026-11-23. 근거: `docs/change_management.md`(CR-001~028), `docs/feedback_to_improvement_map.md`, `docs/user_test_round1.md`, 변경관리내역서, 운영 DB `feedback` 컬렉션 2건(요약은 `docs/user_feedback_2026-11.md`). 사용자 지시(2026-11-23): 테스트 참여·피드백 규모를 **변경관리부터 시작한 전체 변경 건수를 바탕으로** 정의한다(CR 건수와 같지는 않다). 의견은 웹(앱 안 피드백)뿐 아니라 **구두와 메신저(카카오톡)로 들어온 것이 많아** 이것도 피드백으로 표현한다.

## 1. 세는 기준
1. **1건 = 서로 다른 의견 1개.** 한 번의 말에 요청이 여러 개면 의견별로 나눠 센다(예: 앱 피드백 1건에 의견 2개 → 2건).
2. **같은 원인·같은 화면에 대한 반복 보고는 1건**으로 합친다(예: 1차 테스트 6번과 8번은 같은 겹침 오류).
3. **여러 경로로 들어온 같은 의견은 1건**으로 합치고 근거 칸에 경로를 모두 적는다(예: 수준 표현은 1차 테스트 4번과 내역서 No.3).
4. **세지 않는 것:** PM 이 코드·화면을 점검하다 직접 찾은 것(영어 응답 CR-003, 동의 문구 CR-008, TASK 재점검 CR-011, 점검 중 발견한 CR-028 등), 문서 구조 정리(CR-009, 010), 팀 내부 공지·운영 결정.
5. **채널:** 기록 당시 건별로 채널(구두, 카톡, 앱 안, 직접 사용)을 구분해 적지 않았다. 그래서 이 대장은 채널을 **"앱 안 피드백(DB 확인)"**과 **"그 외(구두·메신저·직접 사용 포함, 건별 채널 미기록)"**로만 나눈다. 건별 채널은 사용자가 아는 대로 표시해 주면 채운다(§4).
6. **건수는 사람 수가 아니다.** 한 사람이 여러 건을 낼 수 있다. 참여한 사람 수는 이 문서에서 알 수 없으며 사용자가 알려 주는 값이다(§4).

## 3-1. 규모 구분 (가벼운 변경과 팀 통합 테스트 대상)
사용자 지시(2026-11-23): 내부 구조를 크게 바꾼 변경은 **팀의 통합 테스트 몫**으로 보고, 가벼운 변경만 골라 "적용 건수"로 센다. 아래는 PM 이 대장 36건을 나눈 것이다. **기준은 "화면 문구·표시·소규모 동작 수정으로 끝나고 구조·AI 처리 방식·인증·수집 절차를 바꾸지 않는 것"**이다. 건수를 정해 놓고 맞춘 것이 아니라 이 기준으로 나눈 결과다.

- **화면에서 눈으로 보이는 변경만 세면 16건**(F-02, 03, 04, 06, 11, 15, 16, 18, 21, 22, 23, 24, 25, 26, 27, 29).

- 같은 대장에서 기준만 바꿔도 21, 19, 16 으로 달라진다. **어느 기준을 쓸지는 사용자가 정한다.** 정하지 않은 숫자(예: 14건)에 항목을 맞추어 넣지 않는다.

## 4. 사용자 확인이 필요한 것 (선택)
1. **참여한 사람 수:** 피드백을 낸 서로 다른 사람은 몇 명인가요? 발표에는 "피드백 36건(참여 N명)"처럼 쓸 수 있다. 사람 수를 모르면 "피드백 36건"으로만 쓴다.
2. **채널 표시(선택):** 구두·카톡으로 받은 건이 어느 것인지 알려 주면 대장에 채널 열을 추가해 "웹 N건, 구두·메신저 N건"으로 쓸 수 있다.
3. 설문은 실시하지 않았다(사용자 확인 2026-11-23: mission.md 요건이 아님). 이 대장과 발표자료에는 설문 응답을 쓰지 않는다.
